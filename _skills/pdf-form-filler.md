## What it does

Takes a fillable PDF and a JSON or CSV of values, matches them to form fields
by name (with fuzzy fallback for the inevitable `Text_Field_17`), and writes a
filled copy. Also runs in reverse to pull values out of a stack of returned
forms.

```markdown
# PDF Form Filler

## Procedure

### Filling

1. Dump the field inventory first: name, type, and any existing value.
   Show it to the user before writing anything.
2. Match input keys to field names — exact match, then case-insensitive, then
   normalised (strip underscores and punctuation).
3. Report unmatched keys and unfilled fields. Do not silently drop either.
4. Write to a new file suffixed `-filled`. Flatten only if asked.

### Extracting

1. Read fields from each PDF into a row keyed by field name.
2. Union the field names across all files so the output is rectangular.
3. Write one CSV with a `source_file` column.

## Rules

- Never overwrite the source PDF.
- Checkbox and radio values are export values, not labels. Read the actual
  on-state from the field before setting it.
- If a PDF has no AcroForm layer, say so — it is a scan, and this skill does
  not do OCR.
```

## Why experimental

Field-name matching across PDFs generated by different tools is still
unreliable, and the checkbox export-value handling has known gaps with some
LiveCycle-era documents. Fine for a known form; not yet trustworthy for an
arbitrary one.
